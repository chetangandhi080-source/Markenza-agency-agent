# Environment variables reference

> Every var the system reads, where it comes from, what breaks if it''s wrong.

## Required

| Var | Default | Purpose | Where to get it |
|---|---|---|---|
| `SUPABASE_URL` | none | REST + functions base URL | auto-set by Supabase when you link |
| `SUPABASE_ANON_KEY` | none | Public client key | Supabase dashboard → Settings → API |
| `SUPABASE_SERVICE_ROLE_KEY` | none | Server-side, bypasses RLS | Supabase dashboard → Settings → API |
| `APIFY_TOKEN` | none | Apify auth | https://console.apify.com/account/integrations |
| `SMTP_USER` | none | Gmail address | your account |
| `SMTP_PASS` | none | Gmail App Password | https://myaccount.google.com/apppasswords |
| `SMTP_FROM` | none | `From:` header on outbound | `"Markenza <hi@markenza.ai>"` |
| `CRON_SECRET` | none | Shared secret for cron + tick | auto-generated by `deploy.ps1` |

## Optional (have defaults)

| Var | Default | Purpose | When to change |
|---|---|---|---|
| `HERMES_BASE_URL` | `https://hermes-agent.nousresearch.com` | OpenAI-compatible endpoint | Pointing at OpenAI/Anthropic/Ollama |
| `HERMES_MODEL` | `hermes-3-llama-3.1-405b` | Model name sent in each call | Smaller model, or different provider |
| `HERMES_API_KEY` | empty | Bearer for Hermes | When using a paid endpoint |
| `APIFY_LINKEDIN_ACTOR` | `bebity/linkedin-profile-scraper` | Which Apify actor to call | Switching to a different scraper |
| `SMTP_HOST` | `smtp.gmail.com` | SMTP server | Using Resend/Postmark/SES |
| `SMTP_PORT` | `465` | TLS port | 587 for STARTTLS (not implemented) |

## Setting secrets

For remote (production):
```powershell
supabase secrets set --project-ref <ref> KEY=value
```

For local dev (`.env` file at the repo root):
```
KEY=value
```
Then `supabase functions serve --env-file .env`.

## Verifying what''s set

In Supabase dashboard:
- Settings → Edge Functions → "Manage secrets" shows every var
- In the SQL editor: `select * from settings;` shows per-org config

## Rotating

Every secret can be changed without redeploying functions; new
invocations pick up the new value within seconds.

For `CRON_SECRET`, you also need to update the database GUC:
```sql
alter database postgres set app.settings.cron_secret = '<new>';
```
and re-run the cron migration to reschedule the job.

## What is NEVER in env

- The user''s password (Supabase Auth handles it)
- The user''s offer summary / ICP personas (those go in `settings`
  per org, not env)
- Any lead data (it lives in the DB)
- Anything that should be per-org, not per-deployment

## Per-org override pattern (Phase 5)

Today, SMTP creds live in env. In Phase 5 they move into the
`settings` table so each org has its own. The migration looks like:

```sql
alter table settings
  add column smtp_host text,
  add column smtp_user text,
  add column smtp_pass_encrypted bytea,    -- pgcrypto
  add column apify_token_encrypted bytea,
  add column hermes_api_key_encrypted bytea;
```

`loadConfig()` becomes `loadOrgConfig(orgId)`. Backwards-compat: if
the per-org value is null, fall back to the env var. Both code paths
work during the transition.
